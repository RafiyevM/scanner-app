# Flutter Implementation

The Flutter app in `Projects/MobileApp` is the Android application (display name
**Scanner**). It scans QR codes and 1D barcodes, looks up phone products locally
or through the PostgreSQL ProductApi, and renders explicit result states.

A pure C# core in `Projects/MobileApp.CSharp` mirrors the parser, repositories,
and state machine for host-side use and testing. It has no MAUI or Android UI and
does not produce an APK. See `Root/Documentation/csharp-core.md`.

## Prerequisites

- Flutter 3.47.7 (`./Root/Scripts/bootstrap-flutter.sh` installs it into
  `~/toolchains/flutter`)
- JDK 21
- Android SDK: platform-tools, API 36 platform, build-tools 35.0.0
  (`~/toolchains/android-sdk` is detected automatically)
- An Android device with USB debugging enabled

Flutter downloads its Dart SDK and engine artifacts on first use, so network
access is required.

## Login and Home

The app starts at `LoginScreen`. After a successful sign-in it shows the **Home**
screen; the camera does **not** start until the user taps **Scan code**. The back
arrow on the scanner returns to Home, and sign-out is available on Home.

- **Local demo mode (default):** username `test`, password `test`.
- **Remote mode:** set `authMode = 'remote'`; the app calls the provisional
  `POST {baseUrl}auth/login` contract.
- Sessions and tokens are held in memory only; passwords are not stored or
  logged.
- Languages: English, Azerbaijani, Russian (globe icon).
- Sound: one cashier-style scanner beep when a code is scanned, with a sound on/off button.
  After the result the camera stops; “Scan another code” returns Home, where the
  user taps Scan again.

- **Local demo mode (default):** username `test`, password `test`. This is a
  demonstration gate, not production authentication.
- **Remote mode:** set `authMode = 'remote'`; the app calls the provisional
  `POST {baseUrl}auth/login` contract.
- Sessions and tokens are held in memory only; passwords are not stored or
  logged.

## Products and scan modes

The scanner has a **QR / Barcode** selector above the camera.

- **QR:** QR codes.
- **Barcode:** EAN-13, EAN-8, UPC-A, UPC-E, Code 128, Code 39, Code 93, ITF,
  Codabar.

A product matches by ID, barcode, or QR payload. The result shows a product
illustration, ID, name, description, color, stock quantity, and barcode.

- Quantity > 0 → **Product found / In stock**
- Quantity 0 → **Not in stock** with full details
- No match → **No such product**

The 10 demo products and their codes are in `product-codes.md`. Remote mode uses
the ProductApi described in `postgresql-backend.md`.

## Configuration

Edit `AppConfig` in `Projects/MobileApp/lib/main.dart`:

- `authMode = 'local'` uses the demo credentials
  (`demoUsername = 'test'`, `demoPassword = 'test'`).
- `authMode = 'remote'` uses the provisional `POST {baseUrl}auth/login` contract.
- `dataSource = 'local'` reads `assets/products.json` (10 phones).
- `dataSource = 'remote'` uses `GET {baseUrl}products/{code}` from the
  PostgreSQL ProductApi.
- `apiBaseUrl` must end with `/`.

Current default:

```dart
static const String dataSource = 'remote';
static const String apiBaseUrl = String.fromEnvironment(
  'API_BASE_URL',
  defaultValue: 'https://<tunnel>.trycloudflare.com/',
);
```

The app works over the network with no USB cable. Start the backend and tunnel
with `./Root/Scripts/start-backend.sh`, then build with the printed URL:

```bash
flutter build apk --dart-define=API_BASE_URL=https://<tunnel>.trycloudflare.com/
```

Every scan is sent to the API, which queries PostgreSQL.

For USB development against a local backend:

```bash
adb reverse tcp:8080 tcp:8080
```

Then use `http://127.0.0.1:8080/`.

## Android permissions

After `flutter create`, add to
`Projects/MobileApp/android/app/src/main/AndroidManifest.xml`:

```xml
<uses-permission android:name="android.permission.CAMERA" />
<uses-permission android:name="android.permission.INTERNET" />
<uses-feature android:name="android.hardware.camera.any" android:required="true" />
```

For local HTTP development, add
`android:usesCleartextTraffic="true"` to the `<application>` element. Remove it
for production.

## Compatibility note

`mobile_scanner` was selected at `^6.0.2`. If `flutter pub get` resolves a newer
major version with a different controller callback shape, update
`lib/src/ui/scanner_screen.dart` accordingly. The camera integration is isolated
in that file.

## Security

- No secrets, tokens, or signing material are committed.
- Release builds should use HTTPS.
- Decoded URLs are never opened automatically.
- Decoded payloads are not logged.
